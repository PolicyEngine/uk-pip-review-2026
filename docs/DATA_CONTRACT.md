# Data contract

- **Engine and data pair.** `policyengine[uk]==6.17.2`, which pins policyengine-uk 2.174.1 and the Microcosm UK 2024-25 national build `20261107T020434Z-eeb6093e` (SHA-256 `0a9b77db1c0dee2693cb2d47bad68da34cb662916eee4829942bcd45de581f25`). This is the bundle's certified pair; PIP-specific validation is pending (#1, #4). Model mode refuses any other installed bundle (`pipeline.CERTIFIED_BUNDLE`).
- **Microdata stay private.** No `.h5` file, record-level extract or weight is committed (`.gitignore`, `scripts/check_public_data.py`).
- **Columns the PIP measures read:** `pip_dl_category`, `pip_m_category`, `dla_sc_category`, `dla_m_category`, `age`, `region`, `carers_allowance_reported`, `is_disabled_for_benefits`, `is_severely_disabled_for_benefits` (on `eeb6093e`; `6f918b81` has no `pip_dl_category`, `pip_m_category` or `is_severely_disabled_for_benefits` column, #18). `pip_dl`, `pip_m` and `uc_limited_capability_for_WRA` are formulas, not stored, on `eeb6093e`, so a modifier may wrap them. Builds with microcosm#1550 store LCW and LCWRA, so check `uc_limited_capability_for_WRA` before wrapping it there (#18).
- **England and Wales mask.** Every table keeps England and Wales households only (`pip_review.aggregate`). In a static run households do not interact, so this gives the figures a country test would.
- **Columns the PIP measures need but the data lack** (on `eeb6093e`; `6f918b81` stores `pip_dl_points` and `pip_m_points` for PIP recipients only (−1 otherwise) and no award categories, LCW and LCWRA from the FRS UC admin record and `cares_for_severely_disabled_person`, and no longer stores `is_severely_disabled_for_benefits`, #18): `pip_dl_points`, `pip_m_points`, a score per activity, a health-condition group, hospital stays, award duration and review dates, caring for someone outside the household.
- **Heavy runs.** One data-loading job or production build at a time, under `/tmp/pe-heavy.lock` with at least 14 GB free (`pip_review.heavy`). Model mode runs one simulation per process; its record-level arrays stay in a temporary directory and are never published.
